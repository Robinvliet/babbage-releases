Working with Babbage

Python

Many skills run small Python scripts, among them the document skills for Word, Excel, PowerPoint and PDF files. The model does the same when you ask it to change a value in a spreadsheet: an .xlsx file is not text, so the way to edit one is a script with a spreadsheet library. Babbage can install its own Python for this, so you do not need one on your computer.

What you get

Python 3.13 with pip and five libraries: openpyxl (Excel), python-docx (Word), python-pptx (PowerPoint), pypdf (PDF) and pillow (images). Every version is fixed in this version of Babbage, every download is checked against a checksum that is fixed with it, and nothing is ever updated behind your back.

Installing it

It is not part of the installer: you install it once, from Settings, Tools, in the section Python. A dialog says what will be downloaded and how much space it takes before anything happens: about 56 MB to download and about 168 MB on disk on a Mac, about 52 MB and about 155 MB on Windows. The files come from their official sources (uv from its release page on GitHub, Python from the python-build-standalone project, the libraries from PyPI) and need no administrator rights. The section shows the progress while it runs. The same installation is on the Skills page, next to every skill whose scripts need Python.

It is available on a Mac with Apple Silicon and on Windows (x64).

Where it lives

On a Mac in the data folder, under data/runtime; on Windows outside the data folder, in %LOCALAPPDATA%\Babbage\runtime\python, next to Babbage's own Git. Only Babbage uses it: nothing is added to your own terminal, shell or system Python, and on Windows it does not register itself with the system either. It is not your data, so a backup can leave it out; see Data and backup.

In the terminal

Once it is installed, python and python3 in Babbage's terminal, in scripts and in the command of a monitor are this Python, even when your computer has another one. On Windows, where a Python has no python3 of its own, Babbage puts one next to python. To use another Python, call it by its full path, for example /usr/bin/python3 on a Mac. The model is told whether Babbage's Python is installed, so it knows what it can use.

With the sandbox

Inside the sandbox, the Python folder can be read and run, but not changed (on Windows, unless you linked a folder that contains it, such as your whole user folder). Installing an extra library with pip install is therefore refused there, and the card that appears then offers Run outside the sandbox: you decide, and afterwards you ask the agent to run the command again (see When a command needs the internet). With the sandbox switched off, pip installs directly. Inside the sandbox, an extra library can still go into the conversation's workspace: allow the two PyPI domains when the sandbox asks (pypi.org for the index, then files.pythonhosted.org for the download; each card names its domain, and "Once" covers one command, so choose "This conversation" to let pip through in one go), then pip install --target <folder> and PYTHONPATH=<folder> python3 …; it is gone with the conversation.

Removing and updating

Remove in the same section deletes Babbage's Python; installing it again takes one click and downloads less, because uv stays. A newer version of Babbage may fix a newer Python or newer libraries. The section then says that the installed copy differs, and removing and installing again updates it.
