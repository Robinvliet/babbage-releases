Getting started

First steps

Babbage arrives empty. There is no model inside the app: you connect your own key from a cloud provider, or a model you run yourself. The first time you open Babbage, a short setup takes care of that before anything else.

The interface is in English

Babbage's interface is in English. The language the model answers in follows the language you write in: write Dutch and you get a Dutch answer. And jargon stays in the language it works in, so a tool keeps the name it has in every other tool.

The first start

The first time Babbage opens, you do not see the app yet but a setup of four short steps. The agent introduces itself first, "Hello. My name is Monty.", and you can keep that name or give it another one. Then it asks what to call you. Both names can be changed later: the agent's under Agent settings, yours in Settings.

The third step is the model: "Before we can talk, I need a model to think with." There are three ways.

  • Use an API key. Pick Google or Anthropic, follow the link to the page where you create a key, paste it and click Check and save. Babbage checks the key with the provider once and then stores it in its own .env file on your computer. It never shows the key again and never puts it in a conversation. If the provider rejects the key, the reason appears under the field.
  • Run a model on this computer. Free and private, but slower, and it needs a model server: Ollama or LM Studio. See A model on your own computer below.
  • Connect something else. Open Settings takes you to Models, where you connect your own endpoint or a local server you already run, as described below. When you come back with a model, the setup continues where it was.

There is no way to skip this: without a model, Babbage cannot answer anything. Once there is one, the agent thanks you by name, and Start opens the app on an empty conversation.

If the model disappears later, because you removed the key for instance, a new conversation shows "No model available yet" with Set up a model…, which opens the same setup at the model step.

A model on your own computer

Babbage installs nothing by itself: the model runs in a separate app that you install once. With Run a model on this computer, Babbage first looks for Ollama or LM Studio on your computer.

  • Nothing found. You see "I didn't find a model server yet." with a link to each: Get Ollama (recommended: free, and it runs in the background) and Get LM Studio (an app with its own model browser). Install one, start it, and click I've installed it, check again. In LM Studio, also switch on its local server.
  • Found. "Found Ollama on this computer." with Connect. One click and Babbage is linked; no key is needed for a server on your own computer.

Then you pick the model to think with. A model that can't use tools is greyed out, because Babbage can't work with your files through it. If your server has no models yet, you get a short list of models that fit this computer, chosen by its memory, with a Download button each. A first download is a few gigabytes and takes a few minutes; you can follow the progress on screen. More models are in Discover models under Settings → Models.

One more setting. After you pick a model, Babbage loads it once to see how much context it gets. Ollama gives a model 4k tokens by default (more on a computer with a big graphics card), and Babbage needs at least 16k to work with files and tools. If it is less, the setup says what to change:

  • The Ollama app: go to Settings and set Context length to 16k or more.
  • Ollama without the app: start it with OLLAMA_CONTEXT_LENGTH=16384.
  • LM Studio: open the model's settings, set the context length to 16k or more, and load it again.

Then click Check again. You can also go on with Skip for now; the conversation tells you later if the window is too small.

Adding or changing a model later

Click Settings at the bottom left of the sidebar and go to Models. There are three ways in.

Cloud provider. Under "Add an API (cloud) model", pick Google or Anthropic, paste your API key and click Add. Babbage checks the key with the provider right away, so you know immediately whether it works. You only need one; two is fine too, and then you can switch per conversation. Keys stay server-side and never reach the browser.

Local model. If a local server is already running on your machine, Babbage usually finds it by itself and you see "Ollama found at …" with a Connect button. If you have nothing yet, click Discover models: that searches the models on Hugging Face and downloads one straight to your local server. Free, private and without a key. There is more about this on Models.

Your own endpoint. Under "Your own endpoint" you connect OpenRouter, Groq or your own gateway: a name, the base URL, and the API format that endpoint speaks. Pick that format by what the endpoint speaks, not by the brand name of the model, because a gateway often serves models from another provider.

Your first conversation

Start a new conversation and type your question. There is no mode to pick first: you simply talk, and the agent gets more to work with as you give it more.

The model is the choice on the right in the bottom row of the input bar; the approval level sits on the left, next to the +. The picker shows everything you have access to, cloud and local mixed together. A new conversation starts with the model you used last, so that choice remembers itself.

Everything else follows from settings you can see, in the bar under the input bar:

  • Link a folder with Work in a folder and the agent can read the files in it. Set that folder to Read and write and it may change them and use a terminal as well. What it may do without asking is the approval level, in the bottom row of the input bar next to the +. The agent can also ask you for a folder itself; approving links it. See Working in a folder.
  • For a longer investigation, open the + and pick Deep research, or type /research. That applies to your next message and ends with a saved report.

So there is nothing to switch on to get started. A plain question in a fresh conversation just works.

How deeply the model thinks

The model picker has an Effort row: how thoroughly the model may think before it answers. More means a better considered answer, but also longer waiting and more tokens. The chosen level is shown next to the model name.

The levels are called Off, Low, Medium, High, Extra high and Max, and which ones exist differs per model: Babbage only offers what that model actually knows, with a line explaining anything that is missing. Switch to a model that does not support your level and you will see it fall back.

What you can turn on later

None of this is required, but it is there if you want it:

  • Web search in Settings, so the agent can look up current information. That needs a key of its own.
  • Sources per conversation or per project. The Sources button at the top right (the one with the counter) opens the list; there you add text, a file or a URL, or link a folder. Everything the model can see in this conversation is in that one list. Drag a file onto the input bar and it goes along as an attachment with that message, and appears in the same list. See Sources.
  • Your agent's name and soul, who it is and how it behaves in every conversation, under Agent settings, the item with the agent's avatar and name at the top of the sidebar. See Your agent.
  • Memory, so the agent remembers things about you and your work between conversations. See Memory.
  • Skills to fix its way of working. See Skills.
  • MCP servers to attach tools that Babbage does not have itself. See MCP servers.
